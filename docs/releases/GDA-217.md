# Release Note: GDA-217

## Geo stale-write protection and consumer reliability

This release hardens the live Geo consumer against out-of-order updates and improves the operational clarity of the DynamoDB write path.

### What changed

- Added an optimistic-concurrency guard around Geo upserts using `lastupdatedate` so older events cannot overwrite newer state.
- Kept `softdeleted` and `expireat` values removed on successful refreshes, preserving the expected lifecycle for active features.
- Clarified logging and diagnostics for `ConditionalCheckFailedException` so stale-write rejections are visible without masking the real operational signal.
- Updated the architecture skills to document the live consumer write guard and the relationship between the consumer and the bulk-load replay pipeline.

### Why this matters

Geo management events can arrive out of sequence across distributed systems. Without a guard, a stale update can overwrite newer data and produce incorrect downstream state. The new condition makes the write behavior deterministic: only the newest `lastupdatedate` wins.

### Benefits

- Prevents stale Geo updates from overwriting newer records.
- Preserves the expected feature lifecycle for soft-deleted and expired entries.
- Makes troubleshooting easier by distinguishing stale-write rejections from real write failures.

### Next step

Deploy and validate the consumer in preview and live, then confirm that out-of-order events are ignored cleanly while active feature updates continue to flow normally.
