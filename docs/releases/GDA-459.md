# Release Note: GDA-459

## Name root and name prefix in Geo names

This release carries the `name_root` and `name_prefix` fields of Geo names through the SEO Geo consumer.

### What changed

- The Geo bulk load reads `NAME_ROOT` and `NAME_PREFIX` from the Parquet snapshot and stores them as `nameRoot` and `namePrefix` in the PostgreSQL `geoName` table.
- `mv_geofeature_names` now includes these fields in its `names` JSON.
- The DynamoDB backup and the Lambda mapper expose them as `NameRoot` and `NamePrefix` on each Geo name.
- The bulk load again falls back to default values for its optional tuning settings (DuckDB memory limit, temp and extension directories, CA certificate file, DynamoDB fetch size and write concurrency). Only the bucket, bucket key and secret ID remain mandatory.

### Next step

Deploy and validate in preview and live, then run a full Geo replay so existing records get the new fields.
